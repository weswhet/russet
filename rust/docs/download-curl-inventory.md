# curl option inventory

Phase 1 of the [download implementation plan](plan.md). This inventory counts the curl options used by recipes, so later phases can see which behavior matters in practice. It records option names and counts only. URLs, header values, and credentials are excluded.

Source: the `autopkg/recipes` checkout at commit `0f7b61ab061c77710be4140c404910a11f89fc7b`, and the 151 community repositories in the `autopkg` organization. Each repository was cloned at its default branch, and the counts were taken on October 8, 2026.

The `autopkg/recipes` checkout accounts for 46 of the 5,518 recipes that use a downloader. The community repositories account for the rest.

## Options in `curl_opts`

Option counts are entries across both `URLDownloader` and `URLDownloaderPython` steps. `URLDownloaderPython` ignores `curl_opts` at runtime, so the Python counts show what recipes declare, not what runs.

`request_headers` appears in 296 downloader steps. It is a recipe key, not a `curl_opts` entry, and is generated as `--header` arguments.

## What the counts mean for the plan

- Of the 5,659 downloader steps, 296 set `request_headers`. Only 34 `URLDownloader` recipes supply any `curl_opts`, so most recipes depend only on the generated arguments.
- Body, method, cookie, and insecure-TLS options each occur in only a few recipes. Under the plan, these stay on curl at first.
- The option names are a sample of the community corpus, not a count of every possible invocation. A recipe's behavior also depends on defaults, environment, and processor arguments.
